# FinFlow workspace extension

Mode: Operate. Routes: dashboard, workflows/new, workflows/[id], reports, investigations, data, settings, models, approvals, memory.

THESIS: A finance team should move from a question to source evidence, a reproducible calculation and a deliberate review decision without losing context.

OWN-WORLD: Preserve DESIGN.md and the user-selected dark institutional identity. Graphite, cool white, Geist, tabular amounts, fine rules, sage actions and amber exceptions. Extend existing tokens; no new aesthetic or marketing claims.

STORY: Upload and inspect unfamiliar files; ask a question; examine cited rows, method and execution record; continue the conversation. Return later through searchable history. Personal preferences are visible and editable, distinct from shared workspace records.

FIRST VIEWPORT: Task title and concise purpose, immediately useful controls, then the work. Sources use a catalog and workpaper preview; questions use an open composition with optional examples; answers read vertically with supporting transcript. Settings use ruled sections and mobile records. Financial tables scroll locally; the page does not.

FORM: Code-led extension of the incumbent system. No decision comp or raster assets required. Loading, empty, permission, error, retry and destructive-action states are part of the interface. Minimum 44px touch actions, visible labels and keyboard focus. Test 320, 390, 768 and 1440px widths; preserve meaningful columns and actions on narrow screens.

QUALITY BAR: The task is clear, source identity survives, dates and stale evidence remain visible, and a model output is never presented as an independently certified financial result. Data, calculations and permission boundaries determine the content.

FINISH: Batched browser evidence, independent finish review, and design documentation reconciliation are required.
